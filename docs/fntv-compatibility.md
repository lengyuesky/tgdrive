## 用户已确认

### 交付与服务生命周期

- 使用未修改的官方飞牛影视客户端，直接连接 TGDrive，不要求真实 fnOS 服务器中转。
- 用户在前缀验证失败后明确取消 `/fntv`，客户端使用服务根地址，不再设置 `/fntv` 客户端前缀或管理入口；管理界面在应用中心安装的插件内提供。
- 必须从应用中心安装插件获得该能力，不是主程序默认开放服务或仅提供配置入口。
- 后台协议实现由主程序提供受限能力，插件控制安装、授权和启停，不运行任意插件后台脚本。部分协议升级需要同时升级主程序。
- 安装后先配置账号和目录，再主动启动服务；关闭管理页面不停止已启动的服务。停用或卸载后拒绝新请求、撤销会话并中止相关进行中的传输；卸载默认保留插件数据，不删除网盘文件。已传给客户端的字节无法撤回。
- 更换凭据或撤销授权时，同样中止相关传输并废止旧会话。插件更新成功保留设置和原启用状态，但旧连接需重新登录；更新失败保留旧版和业务数据，新增权限另行确认，不静默扩大授权。

### 内容、数据与连接权限

- 视频来源仅限 TGDrive 已管理的网盘文件，不接本机目录、第三方网盘或外部视频片源。
- 用户手动创建命名的电影库或电视剧库，每库绑定一个已授权目录并包含其子目录，不自动将全盘视频加入。
- 首期仅根据规范文件名、目录结构、网盘同目录中的 NFO 和海报整理电影、季和集，不联网刮削。无法识别的文件仍可浏览播放，不伪造信息，不自动合并同名的不同版本。
- 首期单用户，各目标客户端共用新插件的媒体库与观看进度，不扩展多用户及各自目录权限。
- 与原 Web 影视插件并存，媒体库配置、收藏和观看进度独立保存，不自动迁移、读写或清理原插件数据；仅共用网盘原文件。
- 使用独立的影视连接账号密码，只允许读取显式授权的目录，不把主站管理员会话交给客户端。首期仅手动地址和密码登录，不做扫码、NAS OAuth 或 FN Connect。

### 索引与观看记录

- 首次启动扫描授权目录，之后根据文件变化增量更新，并提供手动刷新。不在每次打开客户端时重扫全库，不为建库下载完整视频。
- 索引只用于内容展示，每次实际读取仍重新检查授权、当前媒体库范围、文件状态及内容版本。
- 文件仍属于授权媒体库时，重命名或移动保留观看进度；内容被覆盖后不继承旧版本进度。
- 文件移出媒体库或撤权时仅隐藏其观看记录，不自动清理；重新加入时仍需匹配原文件身份和内容版本。
- 跨设备以最近有效播放会话的进度为准，旧会话晚到的上报不覆盖新会话，不简单取最大播放位置，允许主动拖回重新观看。

### 播放与验收

- 首期只提供原文件直传和 HTTP Range 拖动，不加入服务端转码、重封装或完整视频落盘缓存。
- 首次播放时允许按需、限量读取视频信息，获取真实编码、时长和轨道，并缓存与文件内容版本关联的小型解析结果。必须有读取字节和时间上限；超出预算或解析失败时明确反馈，不伪造媒体信息，不退回完整视频缓存。
- 依靠官方客户端解码；设备不支持的格式明确失败，不承诺全部格式兼容。
- 首期使用合成的 1080p SDR、H.264 加 AAC 的 MP4/MKV，覆盖起播、暂停、拖动、续播、双音轨及文本字幕。不承诺 4K/HDR、全部编码或图片字幕，也不增加字幕烧录；未测试格式不等于禁止直传，只是不宣称兼容。
- 首验改为用户指定的 Mac 已安装客户端，不使用 Android TV 作为首验环境。只读核验后的准确身份为官方飞牛播放器 `1.12.3 (1123003)` 的 iOS/iPadOS 包在本机 Mac 的兼容运行路径；其他官方客户端随后分别验证，不把此结果当作 AndroidTV/tvOS 实机通过。
- 验收需要真实播放、拖动和续播，登录成功或显示列表不等于播放兼容。
- 完整插件开发前先以最小合成服务验证官方客户端的服务器识别、登录及原文件播放。先前的前缀要求已取消，但仍不能以 HTTP 200、地址生成或第三方客户端表现代替指定官方客户端实际通过。

原交付决策经过见 [ADR-0001](adr/0001-app-installed-fntv-service.md)，当前入口见 [ADR-0004](adr/0004-root-address-without-fntv-prefix.md)，运行边界见 [ADR-0002](adr/0002-host-provided-service-capability.md)，业务数据隔离见 [ADR-0003](adr/0003-isolate-fntv-application-data.md)。

## 已核实的现状

- 现有 `.tgapp` 仅包含页面资源，不执行服务端脚本；不能凭当前插件包注册外部客户端所需的服务端协议。见 [页面应用说明](apps.md)。
- Host 当前单用户。现有影视页面应用的媒体库、收藏和观看进度存放在该应用的私有存储中，并非所有应用共用的影视业务模型。
- Host 已有 Telegram 分块读取和 HTTP Range 能力，但没有现成的服务端视频转码能力。不能将浏览器内转封装当作官方客户端可复用的服务端能力。
- [官方 TV 安装说明](https://help.fnnas.com/articles/v1/start/install-tv)支持手动添加 IP/DDNS 地址和影视账号登录。公开说明及添加服务器截图未提供明确的路径前缀支持证据，不能据此认定 `/fntv` 可用或不可用。
- 已检索的 [官方开放 API 概述](https://developer.fnnas.com/api/overview/)不是完整的影视兼容服务端协议。第三方客户端与代理项目的接口线索也不等于官方客户端兼容证明。
- 本机安装入口为 `/Applications/Runner 2.app`，内层应用为 `/Applications/Runner 2.app/Wrapper/Runner.app`，显示名称“飞牛播放器”，bundle ID 为 `com.trim.media.ios`，版本/构建为 `1.12.3 / 1123003`。公开 bundle、平台和签名元数据与 [Apple 官方商店记录](https://apps.apple.com/cn/app/id6738575136)匹配；商店说明“专为 iPad 设计。未针对 macOS 验证。”不是原生 macOS 或 TV 包。
- 本机应用的主代码签名检查通过，但完整资源包验证报告 `resource envelope is obsolete (custom omit rules)`；不能称为完整签名验证已通过，也不能单凭此报错判定为第三方或遭篡改。此前前缀验证阶段未进入鉴权或播放；根地址续验已进入合成账号鉴权并观察到 MP4 解码画面，最新记录见后文。
- 指定客户端在本地 HTTP 下，输入完整 `/fntv` URL、无协议头地址和末尾斜杠三种形式后，均向根路径发送 `GET /trimcon` 和 `GET /v/api/v1/sys/version`，没有保留前缀；HTTPS 和其他版本未验证。详见 [实测报告](fntv-prefix-verification-20261102.md)。
- 公开第三方客户端存在作品、文件和轨道的独立身份及原画质量协商字段；没有已查到的官方最小媒体 JSON 规范，不能假定仅有文件名/NFO 就能完成官方客户端的原画协商，也不能将第三方播放器的行为当作官方客户端事实。

默认范围仅为本地开发、验证和可安装包产出，不包含提交、推送、公开发布或部署日常服务；需要这些动作时另行确认。

## 第一阶段验证记录

2026-11-02 已建立只监听 `127.0.0.1` 的独立 Node 探针，不连接 TGDrive 数据库、Telegram 或生产服务。自检确认 `/fntv` 返回 200，根路径和 `/v/api/v1/login` 返回 404，没有根路径别名或跳转。探针只记录方法、去除查询参数后的路径、响应状态和时间，不记录请求头、正文、凭据或账号数据。

已通过原生界面启动本机飞牛播放器，同意首次启动的隐私提示并进入登录页；未使用已有账号、未操作已有服务器连接、未提交登录。原生文本输入需通过实际粘贴并逐字段核对，不能把不生效的 AX 赋值当作已填写；地址协议自动切换会重建表单，不能继续使用旧的元素索引。最后一次界面读取时 Mac 锁屏，自动解锁失败，需用户手动解锁后继续。

因此首次尝试状态为 `environment_blocked`，不是 `/fntv` 兼容失败，也不是已通过。该次请求记录仅包含 3 次探针自身的自检请求，没有接收到官方客户端请求；地址保存、登录和播放均未验收。该次临时探针已停止，进程退出和原监听端口拒绝连接均已核验。此为首次尝试的历史记录，不代表续验后的最新状态。

证据与复现脚本保存在本地临时目录 `tmp/fntv-validation-20261102-594mqj/`：`prefix-probe.mjs`、`self-test.json`、`requests.jsonl`、`shutdown.json` 和 `verification.json`。这些是隔离验证材料，不是飞牛协议实现，也不表示认证接口已提供。

用户要求继续后，Mac 已解锁，续验使用独立子目录和新的临时端口。核对三种输入后共收到 6 次真实官方客户端握手请求，均为 `/trimcon` 和 `/v/api/v1/sys/version`，在 `/fntv` 之外返回 404；没有根路径别名或跳转。最新状态为 `compatibility_gate_failed` / `no-go`，不是仍被锁屏阻挡，也不是登录或播放通过。

续验后探针已停止、原端口拒绝连接；本次表单输入已清空，密码隐藏和 HTTPS 开关恢复，历史登录页为空，播放器最后停留在空白登录页。完整插件实现按约定停止。续验报告与截图位于 `tmp/fntv-validation-20261102-594mqj/resume-20261102/`，结论及边界见 [2026-11-02 前缀实测报告](fntv-prefix-verification-20261102.md)。

用户随后取消 `/fntv` 要求，允许按服务根地址继续隔离验证。前缀失败报告保留原结论，但不再构成必须保留前缀的当前需求；根地址验证不得被描述为已经通过。

### 根地址准备与锁屏阻碍

2026-11-03 已准备新的根地址夹具，位于 `tmp/fntv-validation-20261103/root-address-Ser8I1/`。候选接口包括已实测的握手路径、公开第三方客户端的 v1 登录线索，以及仅映射合成文件的原字节 Range 和文本字幕端点；不读取 TGDrive 数据库、Telegram、真实媒体或客户端账号配置。`/trimcon` 的响应规范仍未知，候选空 `code/msg/data` 对象明确标为实验假设；版本值只采用第三方旧文档的原有样例，不能当作官方最低版本或兼容保证。

已生成两条合成音轨的 10 秒 1080p SDR、H.264 加 AAC MP4/MKV 及 SRT 字幕，并用 FFprobe 核对编码、颜色信息和轨道。22 次带自检标记的请求通过：候选握手、正确/错误合成账号、坏 JSON/超限正文、未登录拒绝、原字节与单区间/后缀 Range、HEAD、416、固定字幕、诊断脱敏及停止监听。这里的自检仅证明夹具准备，不证明官方播放、音轨切换、字幕、续播或媒体库兼容。

本次电脑控制工具报告 Mac 锁屏且自动解锁失败，因此没有向新根地址提交官方客户端连接，官方请求数为 0，状态为 `environment_blocked`。自检临时服务已停止并确认原端口关闭，没有启动等待中的原生验证服务。`verification.json`、`self-test.json`、独立自检请求目录和 `evidence-sha256.json` 保存当前结论及范围；需用户手动解锁后继续真实握手和登录验证。

### 根地址续验结果

2026-11-03 续验已确认指定客户端的 v2 登录接口和合成密码 SHA-256 摘要格式；登录响应及非管理员用户信息被接受，客户端进入首页。补齐候选条目字段和封面路径后，官方首页显示一个合成媒体库、两条视频及正确数量，并已观察到合成 MP4 的实际解码画面和带鉴权的原文件 Range 请求。

暂停、拖动、退出续播、MKV、双音轨和文本字幕仍未完成原生验收。旧夹具的字幕关闭标记与退出上报处理不足，新夹具已补齐候选并通过 55 次程序自检；不能据此声称官方客户端通过。末次电脑控制工具再次报告 Mac 锁屏且自动解锁失败，后续验证停止。

本轮临时服务均已停止，最后端口已核验关闭；客户端内两条合成测试连接尚待解锁后清理。本次续验未修改宿主运行代码，未提交、推送或部署。当前结果、原始截图、剩余验收项和复验入口见 [根地址实测报告](fntv-root-verification-20261103.md)。
