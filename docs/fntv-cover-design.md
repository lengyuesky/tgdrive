# 无海报视频封面方案

状态：用户于 2026-11-07 确认完整方案并授权实现。本地候选实现、程序测试、管理页、完整临时宿主协议、两架构媒体组件及指定官方客户端的新封面画面验收已完成，见 [封面验收记录](fntv-cover-verification-20261107.md)。官方客户端使用独立合成连接，确认补图后重新进入页面取得封面；候选源码未提交、未发布。用户于 2026-11-06 已确认范围、来源、显示位置、后台生成、分组选择、截帧预算、失败表现、后台并发、取帧位置、截图尺寸、缓存、自动重试、管理操作和客户端刷新方式。

总体边界见 [飞牛影视兼容设计](fntv-compatibility.md)，宿主能力见 [工程设计](fntv-service-engineering.md)，术语见 [领域术语](../GLOSSARY.md)。当前发布版本为宿主 `0.3.6`、插件 `fntv 0.1.1`，该版本仅使用同目录海报；本轮候选为宿主 `0.3.7`、插件 `fntv 0.1.2`，最低宿主 `0.3.7`。

## 问题与既有证据

宿主 `0.3.6` 的索引仅从视频同目录中寻找命名匹配、大小不超过 2 MiB 的海报，没有接入 Telegram 缩略图或视频截帧。找不到海报时，协议的 `poster`、`posters` 为空字符串，`poster_list` 为空数组。NFO 只参与描述信息和季集组织，有 NFO 并不代表有海报。本轮在 [索引](../src/apps/fntv/index.rs) 和 [协议](../src/apps/fntv/protocol.rs) 接入后台结果。

宿主能够读取网盘原文件第 0 分块所引用的 Telegram 小图，见 [缩略图读取](../src/api/media.rs)。此能力目前使用主站或页面应用的访问入口，不能把其 URL 直接当作 FNTV 封面地址。FNTV 需要在宿主内部复用小图读取，并接上独立影视登录、当前目录授权、服务状态、取消、超时和并发控制。

已有 [封面缓存](../src/apps/covers_db.rs) 按应用隔离，每应用最多 256 MiB；它是可再生缓存，卸载时清理。现有 `cinema` 封面属于另一应用，本方案仅复用宿主缓存设施，所有新状态和图片归 `fntv` 所有。

宿主 `0.3.6` 的运行镜像只包含 FFprobe 及其动态依赖。FFprobe 输出容器和轨道 JSON，不能输出本方案需要的 JPEG 视频帧；本轮 [Dockerfile](../Dockerfile) 已加入 FFmpeg 及其动态依赖。

既有 [原生验收](fntv-native-verification-20261106.md) 覆盖了同目录合成海报和无海报剧集的客户端占位表现，没有验证 Telegram 小图或宿主截帧。不得把这份旧验收当作本方案通过的证据。

本轮只读核对还确认：插件管理页每 3 秒查询配置和服务状态；官方客户端当前没有封面任务查询或索引完成推送接口。既有脱敏原生请求中存在重复列表和图片请求，但与打开详情、进出播放等操作混合，不能证明停留在当前页面时会感知后台补图完成。协议响应的 `Cache-Control: no-store` 也不能保证客户端主动更新页面模型。缺图变为有图的转换表现需要本方案单独验收。

## 用户已确认的行为

| 项目 | 约定 |
| --- | --- |
| 范围 | 所有已入库、缺少可用同目录海报的视频；不按 NFO 或识别状态区分 |
| 来源 | 可用同目录海报 → Telegram 已附带缩略图 → 限量读取视频并截帧 |
| 显示 | 官方客户端列表、详情、继续观看及剧、季卡片；同一视频使用同一张封面 |
| 分组 | 按现有季、集顺序选本组第一张可用真实图片；各集保留自己的图片 |
| 时机 | 索引先发布，后台逐步补图，优先保证建库、起播和播放 |
| 截帧任务 | 默认一个后台任务；前台播放或探测需要资源时让位；停服、撤权、更新取消相关任务 |
| 读取与时间 | 每次任务累计视频读取最多 8 MiB、总耗时最多 10 秒，包含内部各次取帧尝试 |
| 取帧 | 优先尝试约 1、3、5 秒，短视频按时长缩短位置；最多三处，选首张可用非黑画面 |
| 生成图片 | JPEG、最长边 640 像素、最多 256 KiB，保留原始比例；已有图片使用原图 |
| 缓存 | `fntv` 独立拥有，最多 256 MiB，按最近使用淘汰，重启复用、卸载清理，不回写网盘 |
| 失效 | 改名、授权范围内移动可复用；视频内容或图片来源变化时失效 |
| 最终失败 | 客户端占位图及播放入口保留，管理页显示原因并提供重试 |
| 自动重试 | 临时网络错误额外重试两次，间隔 5 分钟、30 分钟；其他终止性失败等待手动重试或来源变化 |
| 手动操作 | 沿用“刷新媒体库”，更新索引及图片来源，并在后台重试待补或失败条目；成功且未过期的封面继续复用，不增加独立重试按钮 |
| 客户端刷新 | 后台完成后，刷新列表或重新进入页面取得新封面，作为首期显示验收标准 |

## 实现约束

### 图片来源与身份

索引只确定条目和候选图片，不为发布媒体库等待图片下载或视频解码。候选图片须符合当前身份、内容版本、目录范围和大小约束；无法使用的候选继续尝试后续来源。视频专属图片优先于同目录共用海报，选择顺序应固定。

Telegram 图片由当前视频第 0 分块的缩略图引用及存储绑定定位。缩略图引用可能因存储迁移而变化，即使视频内容版本未变，缓存也必须跟随实际图片来源失效。保持现有小图读取的 512 KiB 和 JPEG／PNG／WebP 格式限制，并增加 FNTV 的总期限及取消检查。

小图附件读取和视频截帧读取分别约束。截帧中的原视频只能使用现有严格分段能力，不得因为缩略图接口能使用 Bot API 小图读取，就对原视频开放 HTTP 整块下载回退。

封面身份应包含应用、视频节点身份与内容版本、图片来源身份与版本、生成策略版本。客户端获得不暴露上游引用的图片标识。缓存命中不免除当前授权、媒体库归属、节点可见性、应用状态和服务状态检查。

### 后台任务与截帧

索引或来源变化只产生当前媒体库内需要处理的任务，队列受现有索引规模限制。列表和详情查询读取已有结果，不触发同步扫描、下载或截帧。相同任务应合并，避免多个页面或客户端重复生成。

后台任务使用单独的并发控制，不占用前台媒体探测的零等待队列槽位。前台请求需要资源时，后台任务暂停或取消并保留待处理状态。正常停服、撤权或更新造成的取消，不计作网络失败重试。

FFmpeg 输入复用绑定单个授权视频的临时回环入口，继承现有严格读取、对齐读取计费、协议与容器限制、服务取消和子进程清理。清空继承环境，固定图片输出方式，限制输出和错误信息大小。获取必要媒体信息、各次取帧和编码均包含在同一次任务的 10 秒期限中，所有视频读取共享 8 MiB 预算。

只从真实视频轨道选取画面；不将内嵌附图轨道当作正常视频。短视频的采样位置应落在实际时长内。最多三处候选画面，预算用尽即终止，不扩大到整片扫描。生成图片不得拉伸，编码后仍须满足尺寸、格式和字节上限。

发布结果前再次检查任务身份、源版本、当前授权及服务代次。过期、已撤销或已经被新来源替代的任务，不能写入并发布旧图片。

### 缓存与失败

图片和取图状态归 `fntv` 单独拥有；不得借用其他应用的图片记录。图片进入可再生封面缓存，不把图片 BLOB 填入有 32 KiB 单项限制的 FNTV 业务存储。

停止服务保留可复用缓存，重新正常启动后继续处理仍属于当前媒体库的未完成任务。卸载清理封面缓存，不将它与默认保留的账号、媒体库或观看记录混淆。文件撤权或离库后拒绝图片访问，并取消相关任务。

保存与当前来源及策略关联的失败状态。临时网络错误按确认的间隔自动重试，每次新任务仍受完整读取及时间预算限制。格式不支持、预算超限、没有可用画面等终止性失败，不因客户端重复浏览而自动重新生成。源版本变化后重新评估，不复用旧失败结论。

缓存淘汰不是源文件变化；不能为了保持全库图片常驻而立即反复生成被淘汰的图片。再次需要图片时可以安排有限的后台处理，继续保留同一套预算与任务合并规则。

### 协议与管理页

封面继续使用现有作品封面字段和受 FNTV 鉴权保护的图片入口。生成图片用于条目和分组封面，不作为播放时间轴缩略图。播放协商、原文件直传、进度与收藏不依赖封面生成成功。

管理页应能展示待处理、已就绪和失败数量，以及必要的失败原因。对管理页增加能力时，需同步检查宿主 RPC、SDK 类型和固定 `fntv` 权限边界。

“刷新媒体库”等待索引重扫和发布完成，并更新图片来源；本轮已由现有 `fntv.index.refresh` 在索引成功发布后安排当前媒体库内待补或失败条目的后台处理。用户确认保留现有操作入口，不增加独立重试按钮。手动重试重新评估旧失败状态，重复提交合并任务。成功且未过期的封面继续复用，按钮不等待所有图片生成完成。

以客户端刷新列表或重新进入页面后取得新封面作为首期显示验收标准。宿主在后台结果发布后返回对应的新图片身份，保持视频及观看记录身份；不以 `no-store` 推断客户端会自动刷新停留中的页面。管理页仍可通过已有轮询展示后台进度。

## 实现位置

- `src/apps/fntv/`：图片候选、来源及任务状态、受限取帧、协议图片解析、状态查询和生命周期取消。
- `src/api/media.rs`：提取宿主已有的小图字节读取能力，继续使用原 Telegram 小图入口，FNTV 包装承担自己的授权和期限。
- `src/apps/covers_db.rs` 及相关缓存入口：使用 `fntv` 自己的缓存和失效身份，保持配额与卸载清理。
- `Dockerfile`：把受限截帧需要的 FFmpeg 和动态依赖放入 AMD64／ARM64 运行镜像。
- 插件仓库 `fntv/` 与 `sdk/`：封面状态、失败原因及重试管理，保持 API v2 和现有服务权限。

## 验收要求

所有新验证使用临时宿主、临时数据库、内存 Telegram 和带身份标记的合成图片／视频。程序验证与官方客户端显示证据分别记录。

| 场景 | 要验证的行为 |
| --- | --- |
| 有可用同目录海报 | 优先使用海报，保持原图；不启动视频截帧 |
| 没有海报但有 Telegram 小图 | 使用小图，不读取原视频；FNTV 身份和取消约束生效 |
| 两种图片均缺失 | 后台生成真实 JPEG，尺寸和字节符合约定 |
| 无 NFO、未识别视频 | 正常生成或取得图片，浏览和播放能力保留 |
| 无效或超限海报 | 尝试其他候选及后续来源，不因第一个无效匹配阻断全部回退 |
| 黑帧开头、极短视频 | 采样不越过时长，次数与预算受限，选择符合约定的画面 |
| 无法解码、超出预算 | 占位、明确原因、正常播放入口；不下载完整视频、不在重复浏览时重跑 |
| 临时网络失败 | 任务合并、失败持久化和两次自动重试符合约定 |
| 多集与分组 | 每集独立，剧和季选按顺序首张真实可用图片 |
| 改名、移动、覆盖、图片来源变化 | 正确复用或失效，不混用旧内容或旧图片引用 |
| 停服、撤权、更新、卸载 | 取消下载和子进程，拒绝旧身份读取，过期任务不能发布；缓存清理符合约定 |
| 重启与缓存配额 | 缓存复用、失败状态恢复、按最近使用淘汰，不反复全库重建 |
| 刷新媒体库 | 更新索引及来源，后台重试缺图，合并重复任务，复用未过期图片；不增加独立重试按钮 |
| 官方客户端 | 实际列表、详情、继续观看、剧和季显示图片；后台完成后刷新列表或重新进入页面取得新封面 |
| 两架构镜像 | FFprobe 及 FFmpeg 可运行，受限截帧和清理流程通过 |

本轮新增客户端画面与程序证据分别记录在 [封面验收记录](fntv-cover-verification-20261107.md)。该结果覆盖指定客户端及合成素材；其他版本的测试、截图、镜像构建和发布成功不替代新的验收证据。
