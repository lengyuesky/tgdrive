## 隔离范围

所有服务只监听回环地址，使用临时 SQLite、内存 Telegram 和此前生成的合成素材。素材目录及四个文件均校验为普通文件，校验标记、大小和 SHA256 后才运行。没有读取生产 `.env`、连接生产数据库或真实 Telegram，也没有操作真实媒体、真实账户及日常服务。

宿主夹具从未预装 `fntv`。前两次管理页窗口默认 20 分钟，最后一次显式设为 3600 秒，并采用最多 2 秒的服务收尾等待。长期管理事件连接不能使最后一版夹具无限等待。

原始证据位于本地 `tmp/fntv-host-validation-20261105/`，不随源码提交；本文截图保存在 `docs/images/`。Node 验证脚本在这里扮演 HTTP 客户端，实际处理安装、RPC、索引和媒体响应的是 Rust TGDrive 宿主。

## 严格读取与真实探测

默认 `TgApi` 严格入口拒绝调用普通下载。真实 `TgClient` 在无 MTProto、未知路径、相对 HTTP 路径及缺失缓存时，没有向本地计数端点发出 `getFile` 或文件下载；允许目录内本地缓存的偏移和共享预算也通过验证。

MTProto 请求策略采用共同的可测试入口：探测单并发，1 字节读取也预留 512 KiB 对齐段，跨边界重复计费；预算不足时不调用取块闭包。此项使用假取块函数，没有连接真实 Telegram。

显式运行实际 FFprobe 的两组验证通过：

| 验证 | 本轮结果 |
| --- | --- |
| MP4 元数据 | 时长 300 秒，后端区间合计 1572864 字节 |
| MKV 元数据 | 时长 300 秒，后端区间合计 1310720 字节 |
| 缓存 | 重复读取不重新探测 |
| 并发与队列 | 最多 2 个，等待队列为 0 |
| 超时与取消 | 约 10007 ms 超时，读取 262144 字节；停用取消在途探测并释放许可 |

区间计数是后端实际请求／预留范围，不是生产网络流量测量。HTTP 和上游各有 8 MiB 累计预算，原视频未被转码、重封装或完整缓存。输出、轨道数、索引及私有数据的实际限额见 [工程设计](fntv-service-engineering.md)。
