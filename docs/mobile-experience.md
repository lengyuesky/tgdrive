# 移动端与 iPhone 主屏幕体验

## 使用方式

本次提供的是手机网页和「添加到主屏幕」体验，不是原生 iOS 安装包。优先适配 iOS/iPadOS 16.4 及以上 Safari，兼顾 Android Chrome 和桌面浏览器。

手机底部有四个标签：

| 标签 | 内容 |
|---|---|
| 文件 | 最近浏览目录；右上角「+」上传照片／文件、新建文件夹；工具区切换视图、刷新、选择 |
| 传输 | 常驻上传队列、暂停／继续／取消、重新选择原文件和核实服务器进度 |
| 应用 | 已安装应用与可安装目录；宿主内不重复显示主站底栏 |
| 我的 | 账号、收藏、分享管理、回收站、主题、主屏幕说明和系统设置 |

手机单击文件即可打开，更多按钮显示操作面板；进入「选择」后底栏改为批量操作，删除需要再次确认。浏览器返回优先关闭顶层弹层，再退出多选，随后遵循已有路由历史，不插入重复历史记录。系统设置保留未保存修改的离开确认。

### 添加到 iPhone 主屏幕

1. 建议通过 HTTPS 在 **Safari** 打开网盘并登录。
2. 点击 Safari 的 **分享按钮（方框向上箭头）**。
3. 选择 **添加到主屏幕**，确认名称并点击「添加」。
4. 从主屏幕图标打开，进入独立窗口；已在独立窗口中不会重复显示安装说明。

非 Safari 浏览器可先把地址复制到 Safari。在线页面使用浅／深色主题色、Apple touch icon 与 maskable 图标；安装引导可以关闭，自动提示至少间隔 30 天。

### 能力边界

- **在线优先**：没有注册 Service Worker，不缓存私人文件、认证响应或离线阅读内容；完全断网时不保证冷启动可用。
- 文件页只保留一个缓存实例，切换标签保留目录、已加载分页、视图、筛选和滚动。不会为每个目录建立无限缓存。
- 上传调度和文件夹扫描属于登录会话。前台切页不会中断任务，目标目录固定为发起时的位置；上传完成按目录通知文件页，向下浏览或有选择时仅提示刷新，不抢走滚动位置。
- **锁屏、切到后台或系统回收页面可能暂停上传**。返回前台或网络恢复后会查询服务器进度，也可在传输页手动核实；联网状态不等于上传已经恢复。
- 退出登录或受保护接口返回 401 时，立即中止本地请求、哈希线程和扫描，释放文件引用，清空会话队列；不主动删除服务器续传任务。重新登录后需按提示重新选择原文件，已经上传的分块不会重复发送。
- 公开分享的错误提取码和登录失败不视为已有会话失效；注销请求失败会提示错误，不假装已经退出。
- 传输页只管理上传；下载交给浏览器／系统，不展示无法准确观测的下载进度。
- 系统分享只发送已创建的分享页链接，不先下载大文件。不支持系统分享时退回复制；剪贴板受限时显示可选文本供手动复制。

## 布局与实现

| 路径 | 职责 |
|---|---|
| `frontend/src/mobile/viewport.ts` | 手机／平板断点、粗指针、联网与独立窗口状态；VisualViewport 和软键盘判断 |
| `frontend/src/mobile/style.css` | 四边安全区、动态视口、触控尺寸、输入字号、深浅色与减少动画 |
| `frontend/src/mobile/overlays.ts` | 嵌套滚动锁、返回栈、自定义弹层焦点约束与恢复 |
| `frontend/src/mobile/keyboard.ts` | 普通组件事件及 Safari 输入法 229 按键兼容 |
| `frontend/src/components/ResponsivePanel.vue` | 手机底部／全高面板；桌面继续使用弹窗 |
| `frontend/src/components/SessionBoundary.vue` | 认证就绪后建立外壳，忽略过期认证响应 |
| `frontend/src/components/SessionShell.vue` | 四标签、单实例文件页缓存、共享文件选择器与传输依赖注入 |
| `frontend/src/transfers/controller.ts` | 会话级上传、并发／背压、哈希、冲突决策、续传、目录通知与同步清理 |
| `frontend/src/transfers/intake.ts` | 惰性目录扫描、文件选择、拖拽与粘贴；隔离旧扫描及注销后的迟到结果 |
| `frontend/src/session.ts`、`frontend/src/http.ts` | 同步会话失效通知和受保护接口的 401 处理 |

手机断点为 `<=767px`，`768–1023px` 使用紧凑侧栏，桌面保留原有工具栏。粗指针设备也使用不小于 44px 的主要触控目标，文本输入字号至少 16px。页面保留浏览器缩放和系统返回手势。

文件列表独立滚动并填满导航间的可用高度；表单页使用页面滚动。软键盘识别同时要求可编辑元素获得焦点和足够的视觉视口缩小，避免把地址栏伸缩或双指缩放误认为键盘。键盘出现时隐藏底部标签栏，弹层按视觉视口定位。

图片预览最多挂载当前及两侧各一张原图，单指横滑切换、双指缩放、放大后平移，并保留按钮替代操作。视频仍由用户点击才装载媒体地址；全屏按标准 API、iOS 视频 API、页面内沉浸顺序降级，后者有明确退出按钮。关闭预览或离开文件页会立即断开媒体读取。

### 内置应用更新

当前版本为 **图书 1.1.3、漫画 1.0.3、短视频 1.0.2**。图书 `1.1.3` 修复手机横竖屏下“更多”菜单被底部分页栏遮挡的问题。

先更新主站，再在应用中心主动更新已安装的插件；构建不会静默替换安装数据。设置、阅读进度和书签保持原有存储方式，本轮移动改造不新增后端接口或数据库迁移。

设备安全区由宿主统一承担，iframe 只填满宿主提供的可用区域，插件内部不重复添加安全区。退出沉浸恢复进入前的视口设置，主站始终保留 `viewport-fit=cover`。图书和漫画保留原有分页、内容锚点、书签与同步冲突逻辑；短视频使用已有的 API v2 沉浸能力，触摸切换忽略控件起点、多指及取消事件。

### iOS 主屏幕恢复后显示“files，数据 0 KB”

这不是阅读器布局问题，而是主站页面的 HTTP 缓存校验响应错误。原静态服务使用 `not_found_service(index.html)`，
将 `/files/` 等前端路由的正常 HTML 响应强制改成 404；iOS 过一段时间重新校验缓存时，入口文件返回的 304 也被改成 404，
响应正文为空且没有 HTML 类型，因而可能显示系统的 0 KB 文件预览。

- 统一由 `src/web.rs` 提供静态服务，改用保留状态码的 SPA 回退：首次打开返回 `200 text/html`，有效缓存返回标准 `304 Not Modified`。
- 生产主程序和真实浏览器夹具共用实现，避免测试与部署路径不一致；静态资源类型、压缩、HEAD 和缓存校验保持原有语义。
- 不添加定时刷新，不清空登录、上传队列或阅读记录，也不靠前端脚本掩盖错误的 HTTP 响应。
- 新增回归覆盖 ETag／Last-Modified 校验、旧缓存、页面直达、压缩及模拟主屏幕重载、切回前台和重新打开；模拟测试不代表 iPhone 真机验收。

本次隔离验证：157 项后端测试、178 项前端单元测试、44 项应用 Chromium 浏览器测试及类型检查／生产构建通过；后端浏览器夹具的常驻服务测试按设计单独启动。WebKit 与 iPhone 真机未运行。
