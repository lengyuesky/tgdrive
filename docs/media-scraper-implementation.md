## 实现与代码基线

宿主独立 worktree 基于完整提交 `3ad8b3f6b86dd23c49569b2bc2ad41a8cb882ff9`（源码版本 0.3.9），base tree 为 `2e1ee725297f69f5577f85ef28f87db3b145c684`。插件独立 worktree 基于 `9ae5727fd4d76a5acc8f3d4b0e9b99d8efdf5434`。这些 SHA 标识开发基线；本次提交后的宿主完整 SHA 与集成结果记录在插件仓库的 `compatibility.json` 和 `docs/media-scraper-validation.md`。原宿主目录的其他改动保留。

宿主增加固定 `media-scraper` 应用使用的 `scraper.service`、方法白名单、目录授权、迁移 `0027_media_scraper.sql` 和 `src/apps/scraper/`。插件增加独立应用页面，候选选择、资料更新选项、目录扫描与手动执行记录通过共享 SDK 调用宿主。

散放视频先整理到当前父目录下的番号目录，复用已有目录、保留原名。同基本名的不同后缀视频按组处理，配套文件只写一份；同番号不同基本名的版本共享作品资料，保持独立播放入口。明确相关的字幕和专属资料同行，多归属或共用资料须用户选择。默认补缺保留专属与公共资料，主动重刮分别更新 NFO／海报，明确告知整份 NFO 会替换手工编辑内容。

预览与最终移动、覆盖均核对节点、内容版本、名称、位置、目标冲突和相关资料集合。条件不符时拒绝旧计划。SQLite 上传提交保护不随历史记录删除解除；内部上传隐藏于网页续传源文件列表，但继续受清理流程管理。

## 手动步骤、停止与恢复

每次 `scraper.next` 只推进一个步骤，45 秒页面心跳续约；无后台调度或重启自动续跑。停止、关页、撤权、停用和卸载阻止后续步骤，已提交结果保留。在途步骤未确定时先进入待核实；页面以宿主终态确认停止，避免提前显示已取消。

操作记录保留 30 天，清理不删除网盘结果。普通中断核实后手动继续，继续会重新预览；数据库或旧应用快照恢复所得记录只供查看，需重新扫描。恢复丢弃未提交的上传影子，不撤回原实例后来完成的 ready 文件或删除备份之外的 Telegram 附件。

Token 保存于数据库旁独立私有文件，以后端地址和 generation 绑定。页面只回读是否配置；不进入 SQLite、备份或应用恢复快照。恢复清除绑定，更换后端后重新填写；卸载清除应用数据时删除配置、Token 与记录。

## Cinema 与飞牛消费资料

共享 `src/apps/nfo.rs` 拒绝外部实体和超限 NFO，两端读取上限统一为 1 MiB，移除旧 4 KiB 单字段限制。NFO 不自动翻译，保存完整字段与来源；未知评分量表保留原始值，不编造通用评分。

新海报输出精确 2:3 JPEG、最多 2 MiB。两端统一专属海报和目录共用海报的候选顺序，忽略 ASCII 扩展名大小写。Cinema 1.5.1 消费标题、年份和完整简介；番号电影的版本与分段不自动连播，明确电视剧的季集行为保留。

FNTV 单项索引 JSON 预算从旧 32 KiB 调整为 2 MiB + 64 KiB，以容纳完整 NFO 文本转义和文件引用；总索引仍为 8 MiB、10000 项，生成暂存阶段也检查总预算，超限明确失败。飞牛媒体库合计仍最多 3000 条视频。

## 阅读馆翻页问题修复

宿主质量检查修复后的首次完整复测捕捉到一项阅读馆间歇性失败：纯图片 EPUB 在图片解码及缓存回收期间占位缩小，总页数暂时下降，连续翻页可能提前进入下一章。该轮 79 项通过、1 项失败。已在插件端根据原始图片宽度、比例与当前分页容器宽高计算明确显示尺寸，保持解码前后及回收后的占位一致。

真实浏览器的受控图片请求在旧代码上稳定复现横竖屏两项失败。修复后重复 10 项通过，原完整链路中的纯图片章节用例连续 5 次通过，阅读馆独立浏览器验收 25 项通过；最终跨库 80 项全部通过。阅读馆包升级为 1.1.2，其他四包与首轮摘要一致，全部最终包及清单与本轮验收候选逐字节一致。实际命令、结果和包摘要见插件仓库的 `docs/media-scraper-validation.md`。
