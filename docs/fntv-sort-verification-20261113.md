# 飞牛添加日期排序修复验收

2026-11-13，Asia/Shanghai。本地修复基于 `404300611cb10f9a0de7431667cd4f5d32579281`，宿主版本字段为 `0.3.8`。验收使用独立工作区中的未提交候选，未合入原工作区中的搜索、分享、原生接口等改动。本记录描述提交前的验证结果；日常服务未部署。

## 原因与行为

原 `page_rows` 忽略客户端排序条件，始终按标题升序排列；索引还将节点修改时间同时用作添加日期。修复后：

- 普通视频和电影使用 `Node.created_at × 1000` 作为添加日期。文件改名、移动和刷新媒体库不会把旧文件变成新添加文件。
- 剧和季分别使用当前授权集的最大添加日期。日期聚合独立于封面代表集和默认播放集；移出媒体库的集不会影响结果。
- `POST /v/api/v1/item/list` 和 `POST /v/api/v1/favorite/list` 在筛选后、分页前应用排序，同日期使用标题和 GUID 稳定排序。
- 旧索引缺少新字段时，首次读取直接使用已授权节点的真实日期；刷新复用旧索引时也会回填，无需重建媒体库或清除观看记录。
- 文件、作品和轨道日期继续使用 Unix 毫秒；观看位置继续使用秒。

## 官方客户端复现与复验

指定客户端为本机安装的飞牛播放器 `1.12.3 (1123003)`，使用 iOS／iPadOS 包在 Mac 上运行。两轮均连接动态回环端口上的完整临时宿主，使用临时 SQLite、内存 Telegram 和已核验 SHA-256 的合成素材。

通过真实宿主安装分发包 `fntv 0.1.3`，其 SHA-256 为 `b796788a6b55e50ac506d67152d3d022bddbdef49d5d7bb540cf62669ac69380`；仅授权合成目录并创建电影、电视剧两个测试库。插件源码与分发资产未修改。

客户端实际发送 `sort_column: "create_time"` 和 `sort_type: "DESC" / "ASC"`，媒体库页面每页请求 72 条。修复前在界面切换升降序，四部电影仍为相同的标题顺序；修复后界面和返回列表同时改变：

| 场景 | 顺序 |
| --- | --- |
| 修复前，电影添加日期降序／升序 | A 最早添加 → B 最新添加 → C 中间添加 → D 较早添加 |
| 修复后，电影添加日期降序 | B 最新添加 → C 中间添加 → D 较早添加 → A 最早添加 |
| 修复后，电影添加日期升序 | A 最早添加 → D 较早添加 → C 中间添加 → B 最新添加 |
| 修复后，电视剧添加日期降序 | B 更新剧 → A 对照剧 |
| 修复后，电视剧添加日期升序 | A 对照剧 → B 更新剧 |

B 更新剧的第一集早于 A 对照剧，后续集晚于 A 对照剧；该样本能区分“首集时间”与“最近加入的集的时间”。电影添加、修改和标题顺序也故意不同，避免错误字段产生碰巧正确的结果。

另实际切换到标题排序，确认客户端使用 `sort_column: "sort_title"`。原生日期复验后仅补充这个标题字段的降序兼容及对应回归，日期排序代码保持不变；最终源码重新执行程序检查。原生请求与响应的精简证据、对应运行源码摘要见 [合成协议证据](fntv-sort-native-20261113.json)。该记录仅保存排序字段和合成条目，不保存密码、会话令牌、完整请求头或原始请求体。

## 程序检查

新增 5 组行为回归位于 `src/apps/fntv_sort_tests.rs`，覆盖日期双向排序、同日期同标题的稳定顺序、跨页无重复遗漏、收藏和筛选后分页、改名移动、旧索引首次读取与刷新回填，以及剧／季日期和移出媒体库的集。原有文件／轨道日期测试还刻意将修改时间设为创建时间之后，验证两个时间来源及单位。

| 检查 | 结果 |
| --- | --- |
| 修复前 `cargo test --locked fntv_added_date -- --nocapture` | 退出 101；新增 5 组回归全部复现失败 |
| 最终 `cargo test --locked` | 413 通过，0 失败，6 忽略；退出 0 |
| `cargo clippy --locked --all-targets -- -D warnings` | 退出 101；严格门禁被下列已有诊断阻挡 |
| 最终 `cargo clippy --locked --all-targets` | 退出 0；保留 5 类已有告警，无本次修改文件的诊断 |

| 显式 `cargo test --locked fntv_native_fixture -- --ignored --nocapture` | 修复前、后窗口各退出 0 |

严格 Clippy 的已有诊断为：`src/inbox.rs` 的文档注释空行和测试类型复杂度、`src/inbox/interactive_tests.rs` 的锁跨 `await`、`src/extras.rs` 的多余借用，以及 `src/db/upload.rs` 的未使用方法。已逐字节核对这四个文件与基线完全一致，未为了本次排序修复改动收件或上传代码。

原生夹具新增 `TGDRIVE_FNTV_FIXTURE_SORTING=1` 开关，用于生成有区分度的日期样本和启用列表请求字段白名单记录；其他夹具模式不增加排序样本。复现时仍须显式指定已核验的合成素材目录 `TGDRIVE_FNTV_SYNTHETIC_DIR` 与独立输出目录 `TGDRIVE_FNTV_FIXTURE_OUTPUT`。
