# 飞牛演员资料与人物作品页

日期：2026-11-14。用户已确认以下完整方案并授权实施。本文件记录需求共识，实际实现和验收结果另行记录。

## 已确认的产品决定

| 问题 | 结果 |
| --- | --- |
| Q1：演员显示 | 完整显示非空演员姓名；有资料时显示角色和头像，缺头像使用默认占位。 |
| Q2：人物浏览 | 支持影片详情进入人物页，再浏览关联的本地作品。 |
| Q3：既有资料 | 用户可以重新刮削，不为旧刮削结果增加专门复用或索引迁移逻辑；既有 JSON 保持可读。 |
| Q4：影视范围 | 覆盖电影，以及电视剧的剧、季、单集详情。 |
| Q5：实际验收 | 使用本机已安装的官方飞牛播放器，在独立合成媒体库中验收。 |
| Q6：重刮补人物 | 经当前配置的 MetaTube 后端补头像及来源实际提供的简介；取不到时保留姓名，继续影片刮削。 |
| Q7：人物归并 | 有可靠人物身份时按来源身份区分；缺可靠 ID 时，清理首尾空白后按完整姓名归并。不同姓名分别展示，接受同名人物可能误合并的取舍。Gfriends 的姓名 ID 不作为独立的可靠身份。 |
| Q8：电视剧资料 | 剧和季优先使用剧目录 `tvshow.nfo` 的演员表；缺少时分别汇总本剧、本季已收录单集的演员。单集优先自己的演员表，缺少时继承剧级资料。 |
| Q9：作品范围 | 人物页汇总全部当前已授权媒体库中的作品；重叠库同一文件只计一次，计数同样经过授权过滤。 |
| Q10：演员顺序 | 优先使用 NFO 的 `order`；缺少时保留原始顺序。角色和顺序属于作品与人物的关系。 |
| Q11：人物匹配 | 仅采用完整姓名一致且来源身份唯一的候选；重复的同来源同 ID 候选去重。近似匹配或多身份同名时保留姓名和默认头像，显示未匹配。 |
| Q12：资料保存 | 姓名、简介、来源和头像相对路径写入 NFO；头像作为视频同目录的独立 JPEG 配套文件保存，新图片使用独立名称，保留旧文件。完成后的资料展示不依赖 MetaTube 在线。 |
| Q13：补充步骤 | 执行开始后、NFO 写入前补人物资料；每部影片人物后端查询的总预算为 40 秒，有限并发。结果区分已补齐、未匹配和超时。头像确认写入成功后才写本地引用，补充失败不使影片失败。 |
| Q14：人物资料冲突 | 头像和简介分别采用当前授权作品中最近更新且有效的一份。各作品的角色和顺序分别保留。 |
| Q15：作品展示单位 | 电影保留现有独立视频条目及各自播放入口；电视剧按整剧显示，进入后查看季、集。只在某集出现的演员也关联到该剧。 |
| Q16：人物作品排序 | 默认最近入库优先；支持客户端已有标题、入库时间排序及分页。 |

## 实现边界

- 人物资料只通过已配置 MetaTube 的固定人物搜索、详情及主图路由获取。Token 留在宿主；NFO 不保存 Token、带凭据地址或后端配置。
- 读取 NFO 中的 `actor/name/role/order/thumb`，同时保存并读取人物简介和来源 ID。头像引用只解析为网盘本地配套图片，读取时检查其当前版本、目录授权、关联 NFO 与媒体库；不执行 NFO 中的网络地址。
- `tvshow.nfo` 从已识别剧目录寻找，不越过媒体库和应用授权边界。演员汇总与人物图片代表来源均依据当前可访问作品。
- 既有同基本名分组、专属资料优先、目录共用资料保护、取消、失联、撤权和不确定提交保护继续适用。新演员文件采用有界、受限的资料写入步骤，不能变成任意网盘写入。
- 查询失败、缺图和超时属于可见的人物资料不足；取消、撤权与提交不确定仍停止执行，不能被当作普通头像失败吞掉。
- NFO 整份仍最多 1 MiB，索引仍遵守现有总预算。网盘 NFO/JPEG 的读取仍使用 TGDrive 存储；这里的后端离线展示不承诺 Telegram 断网时仍能读取网盘文件。
- 本次实施授权涵盖代码、文档、本机隔离测试与官方客户端验收；提交、推送和部署按已有明确授权范围处理。

## 验收目标

1. NFO 多演员、角色、显式顺序、空值、重复人员、XML 转义与长简介。
2. 唯一精确人物匹配、同名歧义、头像失败、整体预算和取消／撤权；本地头像只在成功提交后进入 NFO。
3. 电影、剧、季、集的演员规则；人物页作品按授权、跨库去重和电视剧聚合。
4. 头像／简介冲突的最新有效来源；资料版本变化和撤权后不能从旧索引或图片缓存暴露内容。
5. 官方客户端实际显示姓名、可用角色和头像，进入人物页，浏览关联作品；分别记录缺头像及电视剧行为。
