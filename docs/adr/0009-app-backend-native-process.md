# 应用后端是宿主启动的受限原生进程

[ADR-0002](0002-host-provided-service-capability.md) 让底层协议留在宿主、应用只控制安装与启停，结果是飞牛影视兼容服务和影视刮削的业务逻辑约 8750 行都写在宿主里，应用包只是管理页；应用仓库 49 条提交中有 10 条必须等宿主先发版。用户于 2026-11-19 确认推翻该决策并全部重写：宿主只提供与内容无关的通用能力，应用可以自带一个用 Rust 编写的应用后端，由宿主作为独立进程启动、停止和重启，必要时常驻，可以自行访问外部网络。

安全边界收窄为只保护网盘数据和宿主自身：容器以 root 启动，宿主为每个应用建立独立的系统用户，应用后端以该用户运行，只能读写自己的数据目录；读写网盘只能经宿主接口并受目录授权约束，宿主的数据库与配置只有 root 可读。验收标准是修一个飞牛协议兼容问题或给刮削增加一个资料来源，都只发布应用包，宿主仓库零改动。

## Considered Options

- 维持纯页面应用、宿主只补通用原语：页面关闭后无法继续响应外部客户端，飞牛服务搬不出宿主。
- WebAssembly 沙箱：隔离更严，但常驻、自由联网和调用 `ffmpeg` 都受限，与用户确认的能力范围冲突。
- 宿主镜像自带脚本运行时：不需要按架构构建，但用户明确选择 Rust 以取得性能。
- Landlock 限制文件访问：依赖部署机内核版本；改为以 root 启动并按应用切换系统用户后不再需要。

## Consequences

- 应用包含原生可执行文件，须为 amd64 与 arm64 分别构建和发布。
- 宿主进程自身以 root 运行，宿主漏洞在容器内的影响面变大。
- 获得某目录授权的应用可以把该目录的内容发送到任何外部地址；这是用户为简化两边开发而接受的代价。
- 宿主不认识书、电影、NFO、番号等任何内容类型；媒体探测与取帧由应用后端调用镜像附带的 `ffmpeg`、`ffprobe` 自行完成。
- 重写不保留已安装应用、目录授权和应用私有数据；网盘文件不受影响。
