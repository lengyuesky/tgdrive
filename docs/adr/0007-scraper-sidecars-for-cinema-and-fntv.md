# 影视刮削产物通过网盘文件供 Cinema 与飞牛影视使用

用户于 2026-11-14 确认：新增应用调用用户配置的 MetaTube 后端，首期为番号影片刮削，在视频同目录保存 NFO 与 JPEG 海报，目前只适配 TGDrive 影视应用 Cinema 和飞牛影视客户端 FNTV。正式刮削结果属于网盘文件，不能只保存在新应用私有资料库或可淘汰的封面缓存中。

通过网盘伴随文件交换影视描述信息，可让两个应用读取共同资料，沿用 [ADR-0003](0003-isolate-fntv-application-data.md) 中各应用独立管理媒体库、收藏和观看进度的边界。代价是必须新增宿主受限写入能力，并补齐 Cinema 与 FNTV 所需的资料读取；目录整理、文件覆盖和任务恢复需要明确处理真实网盘文件变化，不能以应用私有数据恢复代替。

用户在第五、六轮确认：同番号的分段和版本共享选定的作品资料，保留各视频名称与播放入口，分别按视频完整基本名生成 NFO 与 JPEG。已有视频专属资料或目录共用资料默认保留；主动重新刮削时分别选择更新描述文件或海报，并明确预览整份 NFO 替换对手工编辑内容的影响。这样可以准确关联保留原名的视频，代价是同一作品可能保存多份描述文件。

第七轮确认：对于能够独立关联的视频，主动重刮只生成或更新所选视频的专属资料，保留目录共用文件，并在两端统一识别既有专属海报与生效优先级。同基本名、不同视频后缀的文件会共用配套资料，必须一起选中并按组整理，NFO 与 JPEG 只保存一份；各视频仍保留独立入口。这个边界避免更新或移动一个视频时，改变未选中视频的资料与字幕关联。
