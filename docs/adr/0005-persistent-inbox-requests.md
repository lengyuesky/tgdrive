# 独立持久保存收件请求，用户确认后再转存

用户于 2026-11-10 确认私聊收件先选目录、按需改名，最终确认后入库，并要求待办在 24 小时有效期内跨重启继续。收件请求因此独立于网盘文件持久保存，关联原文件消息、目录选择、名称及操作消息；用户确认后才开始 Telegram 转存。

这增加了独立请求状态及恢复处理，但避免复用现有上传占位的错误语义：上传占位属于正在写入的网盘内容，启动清理会回收没有上传会话的占位；等待用户操作也不能阻塞顺序更新消费。将等待与实际转存分开，还能在回调重放或回执丢失时依据同一请求恢复操作，而不是重新收件。完整行为见 [Bot 收件设计](../bot-inbox-design.md)。
