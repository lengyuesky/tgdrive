# 应用平台 0.3.3

现行官方插件为阅读馆、影视、短视频三款。平台保留文件操作、目录授权、应用详情与更新恢复，0.3.3 新增阅读馆替换旧图书/漫画的显式确认。应用继续通过沙箱和 SDK 访问 Telegram 虚拟文件系统，不执行服务端脚本。

## 文件与应用

文件页的右键菜单、更多菜单和手机操作面板提供“打开方式”。只列出已安装、已启用、声明支持该类型的应用。宿主再次校验文件类型和权限，将节点 ID、内容版本及文件信息放入 SDK 的 `ready.launch.file`；应用在读取前重新核验节点身份。

从文件打开时，应用会将所在目录加入内容来源；漫画图片目录以目录自身作为来源。未授权时先由宿主展示目录授权，不能通过启动参数绕过权限。应用里的“在文件中显示”返回父目录并筛选该名称，“文件信息”由宿主展示。

## 授权和来源

- 新安装默认 `scope_mode=none`，没有文件访问权限；首次打开含 `files.read` 的应用时选择目录。
- `selected` 表示允许访问明确列出的目录子树，至少一项；`all` 明确表示全盘。
- 数据迁移保留既有安装的原授权。目录设置必须同时提交 `mode` 与 `paths`，缺少模式会被拒绝。
- `ui.authorizeDirectory` 由宿主选择器和确认界面完成授权，应用无法自行授权。用户取消不会改变范围。
- 授权是安全边界，书库来源和媒体库是内容筛选。每次文件请求、媒体票据使用仍检查最新范围。

## 清单与详情

可选 `integration` 需要 API v2、最低宿主 0.3.0，包括：`file_types`、`directories`、`formats`、`limitations`、`changelog`、`homepage`、`support`、`screenshots`、`data_schema`。

应用详情展示格式、限制、维护链接、更新说明、截图和最低宿主要求。截图来自包内 PNG/JPG/WebP，最多六张、每张不超过 512 KiB，目录截图下载同样核验安装包摘要。链接只接受无用户凭据的 HTTPS。更新确认和批量更新会展示更新说明及新增权限。

## 更新、迁移与恢复

每次更新在同一 SQLite 写事务中保存上一版本的安装包、配置、应用私有数据及数据版本，再切换应用修订。每应用保留一个更新前快照，随数据库备份恢复；不会把可重新生成的封面缓存放入快照。

在“应用设置 → 详情与恢复”查看快照时间并明确确认恢复。恢复会覆盖快照之后的应用进度、书签和配置，同时恢复旧包；保留当前文件授权、启停和固定状态，不修改网盘文件。恢复成功轮换凭据并消费该快照。普通导入和目录更新仍禁止版本倒退。

`lifecycle.migrate(version, callback)` 使用声明的数据版本和 60 秒迁移租约；SDK 每 20 秒续租。回调应幂等并响应取消信号。失败保留旧数据版本，下次打开重试；未知较高数据版本拒绝初始化。迁移回调中的多次私有存储写入不是跨键事务，完整撤销应使用更新快照。宿主记录最近加载、就绪、失败和迁移状态供诊断。

## 同步与任务

保留文件事件 250ms 静默合并、连续事件最长 1 秒的机制。每个服务进程维护最近 256 个文件变更事件，应用用 `files.changes` 游标补齐断线期间的目录变化；重启、超出窗口、范围未知或合并超过 64 个目录时明确回退到完整刷新，不声称未发生变化。游标只用于缓存同步，不能绕过文件权限。

阅读馆报告真实扫描数量，可在宿主任务栏取消。沉浸阅读时隐藏宿主任务栏，保证正文仍占满可用视口。文件正文、封面和视频继续按需 Range 读取。页面标题、保存失败后的离开提示、任务状态通过公开 SDK 接入。

## 独立开发

插件仓库提供 `npm run create -- my-viewer /path/to/new-directory` 和 `npm run dev:host -- /path/to/app`。模拟宿主只绑定本机、使用用户选择的测试文件和页面内存数据，不连接真实网盘。`npm run test:dev-host` 验证真实沙箱握手、文件选择和数据冲突契约。

## 0.3.1 设置统一

历史图书、漫画使用应用内 `library:sources`，删除旧 `source_dir` 设置和旧目录迁移提示。宿主不再替应用写入来源。短视频由自身根据已授权目录初始化现行取材设置。普通同 ID 更新包会清除新清单已不再声明的设置键，现行来源、阅读进度和书签保留；旧配置只存在于用户主动恢复所需的更新前快照中。

## 0.3.3 阅读馆与替换确认

阅读馆 `reader` 统一 TXT/EPUB/PDF、CBZ/ZIP、图片目录，最低宿主 0.3.3。`library.page` 新增 `kind=all`，在一次分页中返回这些格式并去重；`books`、`comics` 仍可用于分类筛选，游标绑定 kind，切换筛选需从首页重新请求。

目录包使用 `POST /api/apps/catalog/{id}/inspect`，JSON 必须携带 `{ "digest": "已选包摘要" }`；宿主必须按摘要找到并核对包，再返回与本地 `POST /api/apps/inspect` 相同的预览字段。预览包括 `manifest`、`digest`、`existing`、`added_permissions`、`replacements: Array<{id,name,installed,has_data}>` 和可空字符串 `replacement_revision`。列表与替换范围指纹均由宿主生成，包括旧 `books`、`comics` 已卸载但仍保留私有数据的情况；前端不从应用列表自行构造指纹。

存在替换项时，确认按钮为「安装并替换旧应用」。点击后才传 `replace_legacy=true`：本地导入在安装查询参数中传入，目录安装在 JSON 中传入。默认 false；安装事务再次检查旧应用与残留数据，未授权时拒绝清理。一键更新对需替换的项目提示单独确认并跳过。
两个安装接口同时接收可空字符串 `replacement_revision`，必须原样回传该次预览给出的指纹。即使阅读馆预览没有替换项、普通安装或批量更新传 `replace_legacy=false`，也须回传指纹，防止预览后新出现旧应用却未经确认就被清理。安装事务重检替换范围及旧应用安装修订；若范围或旧安装 revision 变化，返回 409，需重新预览并确认，不能自动接受新范围。仅阅读进度等数据值的小幅更新、未改变替换范围与旧安装 revision，不会使指纹每次失效。

替换会清理旧应用及其私有阅读进度、书签、偏好、书库配置和恢复快照，不做数据迁移；旧应用封面及运行缓存也会清理。网盘原文件与网盘收藏保留。取消不产生安装或清理，普通同 ID 更新仍保留自己的数据和配置。替换删除的旧应用快照无法从应用详情恢复，完整实例恢复须使用替换前的数据库备份。
