## 安装、授权和运行分别管理

现有应用包是静态页面，宿主在 `src/apps/package.rs` 校验清单，在 `src/apps/mod.rs` 管理安装生命周期，在 `src/apps/runtime.rs` 校验应用修订并分派 RPC。继续使用这一机制提供插件管理页；协议由受限 Rust 宿主能力实现，不添加任意服务端脚本运行时。

实现使用固定应用 ID `fntv`、`fntv.service` 权限和应用 API v2，同时要求 `files.read`、`media.read`。受限能力始于宿主 `0.3.5`，公开 `fntv 0.1.1` 的最低宿主字段为 `0.3.6`，以包含官方客户端兼容修复。宿主与插件仓库的清单校验、主站权限说明、能力声明及 RPC 白名单已接入。其他应用 ID、旧 API、低于包声明的最低宿主版本或缺少前置权限的包会被拒绝。

应用启用与服务启动是两个状态。新安装保留现有“页面应用已启用”的行为，但服务初始停止。用户配置独立影视连接账号、为插件授权目录、创建至少一个有效媒体库后，才能主动启动服务。管理页关闭不改变服务状态。

客户端使用宿主的服务根地址。协议路由为已观察到的 `/trimcon`、`/v/api/v1/...` 和 v2 密码登录入口；管理页仍通过应用中心打开。未安装、应用停用或服务停止时，协议路由应返回拒绝结果，不能落入 SPA 的 HTML 200，也不能开放目录或认证能力。宿主主站首页仍用于主站页面。

已实现的管理能力：

| RPC | 用途 | 权限与副作用 |
| --- | --- | --- |
| `fntv.config.get` | 返回连接账号名称、媒体库、配置是否完整 | 不返回密码、密码摘要或密码校验值 |
| `fntv.account.set` | 设置独立影视连接凭据 | 立即撤销旧影视登录会话并中止相关传输 |
| `fntv.libraries.set` | 保存命名的电影库、电视剧库和根目录身份 | 每个根目录须通过当前目录授权检查；缩小范围立即生效 |
| `fntv.service.status` | 返回运行、索引和封面状态，以及缺图原因 | 只读，不因查询而启动服务 |
| `fntv.service.start` | 启动服务并触发首次索引 | 先核验配置和当前授权，不自动授权全盘 |
| `fntv.service.stop` | 停止服务 | 拒绝新请求、撤销会话、中断尚未完成的传输 |
| `fntv.index.refresh` | 刷新索引及图片来源，后台重试缺图 | 复用未过期图片，不等待全部补图，不重建观看进度 |

实现位于 `src/apps/fntv/`，管理页通过 `Drive.fntv` 调用上述 RPC。能力只向具有对应权限的固定 `fntv` 应用声明；所有调用仍校验主站登录、应用修订和当前授权。管理页保存使用按钮事件和 RPC，支持字段校验及回车；保存成功清空密码输入框，轮询不覆盖正在编辑的账号。

## 业务数据归属与文件身份

媒体库配置、影视描述信息、媒体信息缓存、观看进度、收藏及连接凭据均由 `fntv` 单独拥有，不读写 `cinema` 的私有数据。只共享 TGDrive 的网盘文件与读取能力。

媒体库绑定目录节点身份，并在访问时核验其当前可见路径及插件当前授权。仅存路径会在目录重命名后失去身份；仅存节点 ID 又可能绕过移动后的目录授权，两者都不足以单独授权。

观看进度以“应用、网盘文件身份、文件内容版本”为归属，不以路径、标题或媒体库名称为归属。由此处理以下场景：

- 同一文件改名，或移到另一个仍被授权的媒体库：保留进度，更新组织关系。
- 同一文件出现在重叠媒体库：不产生两份相互竞争的进度。
- 文件被覆盖或新文件复用了旧路径：新内容不继承旧进度。
- 文件移出全部媒体库、回收或撤权：隐藏记录并拒绝读取，保留业务记录。
- 文件重新加入：只有原文件身份与内容版本仍匹配，才恢复原记录。
- 同名的不同文件或不同版本：保持独立条目，不因标题相同而合并。

节点内容版本已有 `Node::content_version()`；当前可见路径已有 `full_path_if_visible()`。新增索引不能替代这些读取时检查。

电影、剧、季、集是组织单元，视频文件与轨道分别有身份。电视剧优先使用可靠的同目录 NFO、目录结构和规范季集文件名；不能只凭同名标题跨目录合并剧集。无法确定归属的视频保留独立浏览与播放入口。

数据复用 `app_data`，因此进入现有私有数据统计、卸载保留或清除、更新恢复快照及数据库备份流程。单项最多 32 KiB，总量最多 10000 项或 8 MiB。`fntv` 的普通 `storage.*` 接口被拒绝，账号校验值及内部业务数据由宿主管理。索引发布时回收离库、版本失效或旧读取策略的探测缓存，观看进度、收藏和已看记录仍保留。

## 连接鉴权与播放会话

指定客户端已使用 `POST /v/api/v2/user/loginByPassword`，密码字段与合成密码的 SHA-256 十六进制摘要匹配。宿主对摘要做加盐 Argon2 校验，不记录或返回密码、摘要及校验值。影视登录仅保存在内存中，令牌为 48 位十六进制，期限 6 小时，最多 32 个会话；每分钟最多 20 次登录尝试。

影视登录凭据只访问飞牛兼容路由。它不能访问主站管理员接口、其他插件私有数据或未授权目录。当前真实客户端的 Authorization 与 Cookie 会话已被夹具接受；纯 Authx 的第三方签名算法尚未被该客户端证明，不以自检结果放宽鉴权。

影视登录会话与播放会话分开管理。打开详情页、查询 `/play/info`、切换管理页或读取媒体描述不能夺取正在播放会话的进度权威。

有效原文件读取获得单调递增的播放代次，首次有效上报将客户端关联标识绑定到该代次。事务检查应用修订、授权与配置快照、文件内容版本及当前进度权威；已结束或旧代次的上报不覆盖新会话，当前会话可主动拖回。文件与轨道日期为 Unix 毫秒，时长和观看位置为秒。兼容 JSON 中的 `watched_ts`、续播 `ts` 和最近播放 `ts` 使用整数秒，内部保留有效上报的小数精度；原生复验确认浮点 `0.0` 会导致客户端列表显示异常，跨接口回归固定了单位和数值类型。

指定客户端上报携带 36 字符 `play_link`，未调用 `/play/play`。实现保守拒绝重叠未绑定播放及未知的新关联，最多保留 512 项关联。2026-11-06 原生复验观察到 MP4 退出续播使用新标识，MKV 播放中切轨复用原标识；合法进度保存且退出后的迟到上报被忽略。`/stream.ip` 在这些协商中复用，并不等于播放关联标识。连续播放及其他客户端仍需各自验证。它们不作为访问凭据，显式夹具只输出比较计数或序号，不输出原值或其哈希。

客户端的剧、季默认播放入口可以使用分组 GUID。播放信息及媒体描述将其定位到当前授权的首个剧集，返回真实作品、文件与轨道身份；分组详情保持 TV/Season 类型，Range 不将库或分组身份当作文件身份。定位使用当前有效条目，撤权后不能凭旧分组读取。

退出请求没有已证明的最终播放秒数，因此保存最近有效上报的位置，不伪造退出时刻。客户端上报间隔及续播误差应在最终报告中说明。

## 增量索引、同目录描述与有界媒体探测

索引只遍历用户创建的媒体库。文件事件和变更游标确定受影响的库，只重新遍历这些库的元数据；未受影响的库及版本未改变的条目继续复用。游标失效或范围未知时全量重建元数据，客户端页面查询不发起扫描。库类型及文件位置参与元数据缓存版本，改变整理方式或目录来源会重新组织条目并保留原文件进度。季目录只识别 `Season` 或 `S` 加数字，其他剧目录按各自节点身份组织。

影视描述与媒体信息分别处理：同目录 NFO 和海报用于内容整理；容器、编码、时长和轨道只能来自真实视频。NFO 中的外部 URL 不触发联网刮削，海报引用不能越过允许的同目录来源。解析应拒绝外部实体、越界路径和超限文件。

当前实现的资源上限已通过显式合成验证；没有连接真实 Telegram 或开展生产负载测试：

| 工作 | 实现上限 | 失败行为 |
| --- | --- | --- |
| 单个 NFO | 64 KiB | 保留未识别条目，不完整下载超限文件 |
| 单张同目录海报 | 2 MiB | 尝试后续候选、小图或截帧，不伪造影视海报 |
| Telegram 附带缩略图 | 512 KiB，JPEG／PNG／WebP | 不可用时继续后续来源，暂时网络错误保留重试状态 |
| 单次封面截帧 | 累计读取 8 MiB、总耗时 10 秒、最多三处取帧 | 保留占位及原文件播放入口，不扩展到完整视频下载 |
| 后台补图 | 单并发，前台播放及探测优先 | 停服、撤权、更新取消；正常取消保留待处理状态 |
| 生成封面 | JPEG、最长边 640 像素、最多 256 KiB | 保留显示比例，包含非方形像素的 DAR；超限明确失败 |
| 单次媒体探测 | 累计读取 8 MiB、总耗时 10 秒 | 明确返回探测失败，不转码、不重封装、不退回完整视频缓存 |
| 并行媒体探测 | 2 个，等待队列为 0 | 超限返回可重试错误 |
| 探测结果 | 输出 128 KiB，持久化单项 32 KiB，最多 64 条轨道 | 超限或损坏明确失败，不保存原视频 |
| 索引 | 32 个库、合计 3000 个视频、单库扫描最多 20000 个文件 | 超限停止发布新索引并报告错误 |

FFprobe 使用只绑定单个授权节点的临时回环读取入口，清除继承环境，只允许指定输入协议及容器。HTTP 读取与上游分段请求分别累计预算，超时和撤销会终止入口及子进程。探测缓存绑定内容版本和读取策略版本。

`fntv` 的原文件与探测读取使用 `TgApi` 的严格分段入口。真实客户端只使用已存在的允许目录内本地绝对缓存，或 MTProto 文档分段；相对 HTTP 路径和 `getFile` 回退会被拒绝。MTProto 探测固定单并发，每次请求前预留完整 512 KiB 对齐段，所有 Range 共用 8 MiB 预算。普通后端没有明确实现该入口时直接失败。媒体响应发送前预读首字节，避免先返回成功响应再发现不安全后端。

本地候选按同目录海报、Telegram 已有小图、受限截帧的顺序补图。索引先发布，单并发后台任务随后处理；列表只装饰已有状态，不同步下载或截帧。FFmpeg 复用单节点回环读取，探测、各次取帧及编码共用 8 MiB／10 秒预算，清空子进程环境并限制协议、分配、输出及错误信息。

图片进入 `fntv` 私有的 256 MiB 封面缓存，任务状态单独持久化，不随图片 LRU 淘汰丢失。内容或来源变化使旧结果失效；改名和授权范围内移动可复用。缓存淘汰不触发反复全库生成，图片再次请求时可安排后台处理。停止保留缓存，卸载清理；普通 `covers.*` RPC 对 `fntv` 拒绝，内部缓存由宿主管理。暂时网络错误额外重试两次，等待 5 分钟和 30 分钟；其他失败通过现有刷新入口或来源变化重试。

完整行为见 [无海报视频封面方案](fntv-cover-design.md)，本轮证据见 [封面验收记录](fntv-cover-verification-20261107.md)。2026-11-06 之前的海报、探测及原生播放证据不替代新增封面的官方客户端画面验收。

解析结果缓存键包含视频内容版本；外部字幕和 NFO、海报各自也要关联其源文件版本。字幕改变不等于视频内容改变，不应丢失视频观看位置。

## 原文件传输与生命周期中断

播放复用宿主原文件和单区间 Range 读取，不改变容器或编码。认证通过后，每次读取仍检查应用状态、服务代次、当前可见路径、媒体库归属和文件内容版本。已经缓存的索引或曾签发的媒体身份不能跳过检查。

仅在请求开始检查权限不足以满足停用与撤权要求。正在传输的响应必须绑定可撤销状态；停用、卸载、凭据更换、撤权或更新成功应中止其后续输出。已经发送到客户端的字节仍无法撤回。

现有 `EventBus` 可以传播应用与文件变化，但异步事件不能成为唯一的权限核验。停止操作成功返回前应完成同步失效，数据流本身还需要中断检查。其他目录的文件变更不应无条件打断全部播放。

更新成功保留配置、业务数据和原运行状态，并废止旧连接；更新失败保持旧版继续服务。新增权限必须进入安装预览。卸载默认保留业务数据但停止服务，重新安装不能仅因保留旧记录而自行启动。

## 验证顺序

指定官方客户端的首验核心关卡已于 2026-11-04 取得隔离合成证据，明确覆盖组合与限制见 [播放续验记录](fntv-playback-verification-20261104.md)。随后在临时 SQLite、内存 Telegram 和合成媒体中实现并核验宿主能力及可安装包。

宿主检查应覆盖真实边界：未安装和停止时的协议拒绝；影视凭据不能访问管理员接口；媒体库范围和节点版本；停用、撤权、更新及卸载中断正在传输的字节；旧播放会话不能覆盖新会话；改名、移动、覆盖和重新加入的进度行为；探测的实际字节、时间、并发及进程清理；默认保留与明确清除私有数据。

已通过真实应用中心导入、授权、账号和电影／电视剧库保存、启停及关闭页面后的持续运行；程序客户端也完成原字节 Range、207 秒进度和网络传输生命周期验证。原 `v0.3.5` 完整 Docker 镜像的 AMD64、ARM64 构建和 FFprobe 运行检查已通过，解决了此前的构建阻碍；本轮协议修复收录于宿主 `0.3.6`。

指定客户端已连接完整临时 TGDrive 宿主，实际完成核心播放集合与季页首集起播，结果与源码范围见 [2026-11-06 原生验收记录](fntv-native-verification-20261106.md)。其他设备、HTTPS、4K/HDR 和未测试播放组合分别验收。
